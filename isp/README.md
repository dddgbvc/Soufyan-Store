# ياقوت — وحدة مزودي الإنترنت | نسخة فانيلا

نسخة **فانيلا** من `yaqoot-isp-engine`: ملف HTML واحد، بلا أطر عمل، بلا خطوة
بناء، بلا اعتماديات، بلا خادم.

```
isp/index.html      ← التطبيق كاملاً (HTML + CSS + JS في ملف واحد)
isp/verify-ui.mjs   ← فحص واجهة اختياري بـ Playwright
```

## التشغيل

افتح `isp/index.html` بالمتصفح — نقرتان مزدوجتان تكفيان، أو عبر أي خادم ثابت:

```bash
npx http-server -p 8899 .
# → http://localhost:8899/isp/
```

بيانات الدخول للمزود التجريبي: **`agent` / `demo1234`**

## ما الذي يُثبته هذا العرض

الفكرة المركزية للمحرك: **الواجهة تُبنى من القدرات المعلنة، لا من اسم المزود.**
لا يوجد في الملف كله سطرٌ واحد من نوع `if (provider === '…')`.

بدّل «ملمح المحاكاة» من الشريط العلوي وراقب اللوحة وهي تعيد بناء نفسها:

| الملمح | ما يحاكيه |
|--------|-----------|
| `full` | معظم القدرات — جلسات، محفظة، حسابات تجريبية |
| `basic` | مشتركون وباقات وتجديد فقط |
| `readonly` | لا عمليات تغيير إطلاقاً |
| `legacy` | واجهة قديمة: بلا سرعات، بلا بيانات اتصال، قدرات `unknown` |
| `ftth` | عُقد ألياف، بلا تصفير MAC |
| `wireless` | أبراج وقطاعات وبيانات إشارة، بلا محفظة |

في نسخة Next كان هذا متغيّر بيئة `ISP_MOCK_PROFILE` يحتاج إعادة تشغيل الخادم؛
هنا صار مُبدِّلاً حيّاً، وهذا الفرق الوحيد الذي *يحسّن* العرض.

ثلاثة أشياء تستحق التجربة تحديداً:

1. **`basic`**: بطاقة المحفظة تبقى ظاهرة لكنها تشرح سبب عدم الدعم
   (`showWhenUnsupported`)، بينما تختفي بطاقة الحسابات التجريبية كلياً — لأن
   المدير يستطيع فعل شيء حيال الأولى ولا يستطيع حيال الثانية.
2. **`legacy`**: «احسب خطة التجديد» لا يعرض تاريخ انتهاء جديداً، بل يقول إن
   المزود لا يُرجعه. لا تاريخ مخترع.
3. **دور «صرّاف»** من الشريط: تختفي ودجات المال قبل أي اعتبار آخر — الصلاحية
   تسبق القدرة، والقدرة تسبق تفضيل المستخدم.

## الشاشات

| المسار | المحتوى |
|--------|---------|
| `#/` | اللوحة — ودجات مُولّدة من سجل الودجات + بيان القدرات |
| `#/subscribers` | سجل المشتركين، أعمدته مشتقّة من القدرات، مع لوحة ملف المشترك |
| `#/capabilities` | مصفوفة قدرات المزودين مع تفصيل كل خانة |
| `#/checks` | ٧٥ فحصاً تعمل في المتصفح على الكود نفسه الذي يرسم الشاشات |

## خريطة الملفات: من Next إلى الفانيلا

الملف مقسوم إلى ثلاثين قسماً مرقّماً بنفس ترتيب طبقات المشروع الأصلي:

| القسم في `index.html` | الأصل |
|------------------------|-------|
| ١–٥ النواة | `modules/isp/core/{money,freshness,errors,result,types}.ts` |
| ٦–٨ محرك القدرات | `modules/isp/capabilities/{keys,manifest,resolver}.ts` |
| ٩ حساب الانتهاء | `modules/isp/subscriptions/renewal.ts` |
| ١٠ سجل الودجات | `modules/isp/widgets/registry.ts` |
| ١١–١٣ عقد المحوّل وسجله | `modules/isp/providers/core/{auth,adapter,contract,registry}.ts` |
| ١٤–١٦ المزود التجريبي | `modules/isp/providers/mock/{profiles,data,adapter}.ts` |
| ١٧ Earthlink | `modules/isp/providers/earthlink/*` |
| ١٨ الإقلاع | `modules/isp/providers/bootstrap.ts` |
| ١٩ خدمة المزودين | `lib/isp/{providerService,providerSession}.ts` + `app/api/isp/*` |
| ٢٠–٢٢ المكوّنات | `components/glass/*`, `components/form/DynamicForm.tsx` |
| ٢٣ نافذة الدخول | `components/provider/ProviderLoginModal.tsx` |
| ٢٤–٢٦ الحالة والهيكل | `components/isp/{ProviderContext,Shell}.tsx` |
| ٢٧–٢٨ الشاشات | `app/isp/**` |
| ٢٩ الفحوصات | `tests/*.test.ts` |

بديل React هو `D.el()` في ثلاثين سطراً. لا `innerHTML` في الملف إطلاقاً: كل نص
يمرّ عبر `textContent`، فلا مسار لحقن HTML من بيانات مزود.

## ما لم يُنقل — وهذا مقصود

هذه نسخة واجهة تعمل بالكامل في المتصفح. ثلاث طبقات في المشروع الأصلي لا معنى
لها بلا خادم، ولم تُزيَّف هنا:

- **طبقة Supabase و SQL** (`supabase/migrations/*`, RLS، دوال `SECURITY DEFINER`،
  `isp_guard`, `isp_renewal_post`, `isp_idempotency_begin`). ودجات الدفاتر —
  إيراد اليوم، كلفة المزود، الربح، آخر التجديدات — تعرض «غير متاح» صراحةً، لا
  صفراً. الصفر يُقرأ «لا مبيعات اليوم» وهي كذبة مختلفة تماماً.
- **جلسة المزود على الخادم.** في نسخة Next تُرسَل بيانات الدخول إلى مسار خادم،
  وتبقى مادة الجلسة هناك، ولا يرى المتصفح إلا مرجعاً معتماً. هنا لا خادم، فكل
  شيء في ذاكرة الصفحة: **لا يُكتب شيء في `localStorage` ولا `sessionStorage` ولا
  في عنوان الصفحة، ويزول كل شيء بالتحديث.** هذا مقبول لأن المزود هنا محاكاةٌ
  داخل الصفحة نفسها. **مزودٌ حقيقي بمفتاح حقيقي يحتاج طبقة خادم** — لا تضع
  اعتماد وكيلٍ حقيقي في هذا الملف.
- **التحقق الثابت من الأنواع.** لا TypeScript، فلا `tsc --noEmit`. ما يعوّض ذلك
  جزئياً هو `#/checks`، ومنه فحص العقد الذي يمنع «الزر الوهمي».

## إضافات على واجهة نسخة Next

اثنتان، وكلتاهما تستهلك بيانات محوّلٍ موجودة أصلاً بلا سطح يعرضها:

1. **لوحة ملف المشترك** بأزرارٍ مشروطة بالقدرة (تجديد، تفعيل، إيقاف/تشغيل، قطع
   جلسة، تصفير MAC). كانت مُهيّأة في طبقتَي المجال وSQL بلا واجهة، فبقيت
   `planRenewal` و`renewSubscription` ودفتر الحماية من التكرار وحالة
   `REQUIRES_RECONCILIATION` بلا طريقة لتجربتها.
2. **ودجة «حركات المحفظة»** — القدرة `walletTransactions` كانت معلنة ولها دالة
   محوّل ولا أحد يستهلكها. إضافتها كانت إدخالاً واحداً في سجل الودجات، وهذا
   بالضبط ما تَعِد به البنية.

## الفحوصات

`#/checks` يشغّل ٧٥ فحصاً على الكود نفسه الذي يرسم الشاشات: حساب النقود، دلالات
التجديد الخمس، حلّ القدرات، التجميع عبر عدة مزودين، ظهور الودجات، نضارة
البيانات، إخفاء الأسرار، **عقد المحوّل على الملامح الستة كلها**، وحتمية البيانات
والحماية من التكرار.

الفحص الأهم واحد: قدرةٌ معلنة «مدعومة» يجب أن تقف خلفها دالة محوّل حقيقية. بدونه
يحصل المشغّل على زرٍّ ينفجر. مع الفحص، «الزر الوهمي» فشلُ فحصٍ لا عطلَ إنتاج.

فحص الواجهة الاختياري (يحتاج Playwright مثبَّتاً):

```bash
npx http-server -p 8899 .
node isp/verify-ui.mjs          # ٣٥ فحصاً + الـ٧٥ داخل الصفحة
```

## حدود معروفة

- الخطوط من Google Fonts عبر `<link>`. بلا إنترنت تعود الصفحة لخطوط النظام
  وتبقى سليمة، لكن الشكل يختلف.
- بلا شبكة، `#/checks` وكل الوظائف تعمل: لا شيء في المنطق يعتمد على طلب خارجي.
- `color-mix()` و`backdrop-filter` تحتاجان متصفحاً حديثاً. المتصفح القديم يفقد
  الزجاج والألوان المشتقّة، لا الوظيفة.
- ملف واحد بحجم ~٢٧٠ ك.ب. هذا ثمن «بلا خطوة بناء» المقصود.
