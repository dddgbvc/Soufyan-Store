# تجربة جهاز 24 🕰️ — Trial24

نظام مستقل داخل ERP «مركز سفيان للهواتف» لإدارة **تجربة الجهاز 24 ساعة قبل قرار الشراء**.
نسخة **فانيلا** بالكامل: JavaScript وHTML وCSS قياسية، وخادم Node بلا أي حزمة خارجية — `dependencies: {}`.

> التجربة هنا **مرحلة من رحلة الشراء**، لا إعارة: تنتهي بشراء أو إرجاع أو تمديد.

---

## ✳️ شرط أساسي في التصميم: بلا تصوير

لا يوجد في النظام أي التقاط صور، ولا Camera Capture، ولا Photo Evidence، ولا طلب تصوير الجهاز عند التسليم أو الاستلام.
**التحقق يقوم على بيانات الجهاز وحالته المسجّلة في النظام:**

| بدل التصوير | ما يفعله النظام فعليًا |
|---|---|
| إثبات هوية الجهاز | مطابقة IMEI/Serial المُدخل مع سجل الجهاز (`assertSerialMatches`) |
| إثبات حالة التسليم | **لقطة حالة** تُجمَّد داخل التجربة: البطارية، الدرجة الظاهرية، الملحقات، الفحوص الوظيفية |
| إثبات حالة الاستلام | فحص مقارن ببنود محددة أمام لقطة التسليم + ملاحظة مكتوبة إلزامية عند أي فرق |
| إثبات المسؤولية | سجل تدقيق كامل: من، متى، أي جهاز، أي عميل، الحالة قبل وبعد |

## 🚀 التشغيل

```bash
cd erp/trial24
node server/server.js          # ثم افتح http://localhost:4024
```

بلا تثبيت، وبلا خطوة بناء. يتطلب Node 18 أو أحدث.

```bash
node server/server.js --empty  # تشغيل بمخزون ومستخدمين فقط، بلا تجارب تجريبية
node server/seed.js --force    # إعادة تهيئة البيانات من الصفر
node tests/run-tests.js        # 55 اختبارًا لمنطق الأعمال
PORT=8080 node server/server.js
```

البيانات في `data/trial24.json` (كتابة ذرّية: ملف مؤقت ثم إعادة تسمية).

**مستخدمو العرض** (يُبدَّلون من زر المستخدم أسفل الشريط الجانبي):

| المستخدم | الدور | الصلاحيات |
|---|---|---|
| سفيان الجبوري | مدير | كل شيء: تمديد، إلغاء، تجاوز، تحليلات، تدقيق، إعدادات |
| أحمد كريم / زيد الساعدي / نور العبيدي | موظف | إنشاء تجربة، إرجاع، إتمام بيع |

## ⏱️ الوقت: مرجع واحد فقط هو الخادم

المتطلب الأهم: **لا يجوز أن يُعيد ضبطَ التجربة تحديثُ الصفحة، ولا فتحُها من جهاز آخر، ولا تغييرُ ساعة الجهاز.**

1. `startAt` و`endAt` يُحسبان على الخادم عند التأكيد ويُخزَّنان — لا تُرسل الواجهة أي وقت.
2. الواجهة تزامن ساعتها عبر `GET /api/time` مع تعويض نصف زمن الرحلة:
   ```js
   offset = serverNow + rtt / 2 - performance.now();
   const serverTime = () => performance.now() + offset;   // clock.js
   ```
3. المرجع هو `performance.now()` وهو عدّاد **رتيب** لا يتأثر بتعديل ساعة النظام ولا بالمناطق الزمنية.
4. إعادة المزامنة كل 45 ثانية، وعند العودة من الخلفية، وعند رجوع الاتصال. تأخّر المزامنة يظهر كمؤشر تحذيري بدل عرض أرقام مضلّلة.
5. اختلاف ساعة الجهاز عن الخادم يظهر كتنبيه معلوماتي فقط — العدّاد لا يتأثر.
6. مؤقّت واحد كل ثانية يقود كل العدّادات في الصفحة (`onTick`) بدل مؤقّت لكل عنصر.

درجات العدّاد الأربع تُشتق من الوقت المتبقي حسب عتبات الإعدادات: **طبيعي** ← **تقترب من النهاية** (≤ ٣ ساعات) ← **حرِجة** (≤ ساعة) ← **انتهى الوقت**.

## 🔄 آلة الحالات

```
                     ┌──────────────── تمديد ─────────────────┐
                     ↓                                        │
 [إنشاء] ──→ active ──(انقضاء المدة على الخادم)──→ expired ────┘
              │                                        │
              ├──────────→ purchased  (Trial → Sale، مع حفظ رابط التجربة)
              ├──────────→ returned   (Trial → Returned → Inventory)
              └──────────→ cancelled  (مدير فقط)
```

| حالة الجهاز | متى |
|---|---|
| `available` → `on_trial` | عند تأكيد التجربة — يُقفل فلا يُباع ولا يُحجز لغير هذا العميل |
| `on_trial` → `available` | عند الإرجاع أو الإلغاء |
| `on_trial` → `sold` | عند الشراء |
| `on_trial` → `maintenance` | إرجاع بفرق في الحالة مع اختيار التحويل للصيانة |

انتهاء المدة **لا يحرّر الجهاز تلقائيًا** — يبقى مقفولًا حتى استلام فعلي، وهذا ما تقيسه بطاقة «بانتظار الإرجاع».

## 📋 القواعد المطبَّقة على الخادم

كل قاعدة أدناه مفروضة في طبقة الأعمال ومغطّاة باختبار — إخفاء الأزرار في الواجهة راحة بصرية فقط:

**الإنشاء** — العميل موجود وغير موقوف · لا تجربة مفتوحة أخرى للعميل نفسه · الجهاز متاح · IMEI/Serial مطابق · العربون ≥ الحد الأدنى · إقرار الشروط · المدة ≤ الحد الأقصى.

**التمديد** — عدد التمديدات ≤ `maxExtensions` · التمديد الواحد ≤ `maxExtensionHours` · المدة الكلية ≤ `maxTotalDurationHours` · موافقة المدير إن اشترطتها الإعدادات (طلب الموظف يُرفع كطلب معلّق ولا يُطبَّق) · طلب مخالف للسياسة يُرفض عند مصدره فلا يصل للمدير أصلًا · التمديد يُعيد التجربة المنتهية إلى `active` ويُعيد ضبط التذكير للموعد الجديد.

**الإرجاع** — مطابقة IMEI · فحص مقارن بلقطة التسليم · ملاحظة مكتوبة إلزامية عند أي بند غير مطابق · الاستقطاع ≤ العربون · قياس التأخير عن الموعد.

**الشراء** — مطابقة IMEI · الخصم ≤ السعر · احتساب العربون من الفاتورة · إنشاء `SAL-YYYY-NNNN` يحمل `trialId` الأصلي دائمًا.

**تجاوز السياسة** — يتطلب صلاحية `trial.override` **و**سببًا مكتوبًا، ويُسجَّل حدث `POLICY_OVERRIDE` مستقل.

**الحالات النهائية** — أي إجراء على تجربة مغلقة يُرفض بـ `TRIAL_CLOSED`.

## 🔔 الإشعارات والمجدول

مجدول داخلي كل 20 ثانية، ويُستدعى أيضًا قبل كل نداء API — فتبقى الحالات صحيحة، **ويُعالج المتأخرات فور التشغيل إن كان الخادم متوقفًا**.

| الحدث | متى | إلى من |
|---|---|---|
| `TRIAL_STARTED` | عند التأكيد | المدير — مع العميل والجهاز وIMEI والموظف والبداية والنهاية والمدة والعربون |
| `TRIAL_ENDING_SOON` | قبل الانتهاء بساعة (قابلة للضبط) | العميل + الموظفون + المدير |
| `TRIAL_EXPIRED` | عند انقضاء الـ24 ساعة | المدير + الموظفون المخوّلون + العميل |
| `TRIAL_RETURNED` / `TRIAL_PURCHASED` / `TRIAL_EXTENDED` / `TRIAL_CANCELLED` | عند الإجراء | المدير + الموظفون + العميل |
| `TRIAL_EXTENSION_REQUESTED` | طلب موظف بانتظار الموافقة | المدير |

كل حدث يُسجَّل داخل النظام ويظهر في درج الإشعارات. رسائل العملاء تُولَّد جاهزة مع **رابط واتساب** (قناة المتجر الفعلية) ويُسجَّل إرسالها — بلا أي خدمة خارجية أو مفتاح API.

## 🎨 نظام التصميم

لغة بصرية تجمع انضباط **Fluent** مع هدوء واجهات **Apple**، بلا محاكاة حرفية لأي واجهة:

- **البطاقة** للمعلومة الأساسية: سطح صلب، حدّ واضح، ظل خفيف.
- **اللوح الزجاجي** (Liquid Glass / Glassmorphism) للطبقات الثانوية والعائمة: الشريط الجانبي، الشريط العلوي، النوافذ، الدرج، اللوحات التوضيحية — شفافية + `backdrop-filter: blur + saturate` + حدّ ضوئي + لمعة تنساب ببطء.
- **العدّاد هو البطل البصري** في تفاصيل التجربة: حلقة تقدّم بأرقام أحادية العرض، ولونها يتبدّل مع درجة الإلحاح.
- **حركة هادئة**: تلاشٍ، تحجيم، نابض خفيف، تقدّم، ضبابية خفيفة — ونبضة واحدة فقط في الحالة الحرِجة. كل ذلك يتوقف تحت `prefers-reduced-motion`.
- **سمتان** داكنة وفاتحة، وواجهة RTL عربية بالكامل بخصائص منطقية (`inset-inline`) واستجابة حتى عرض الهاتف.
- إمكانية وصول: أهداف لمس مريحة، حلقات تركيز واضحة، حصر التركيز داخل النوافذ، إغلاق بـ Esc، وعناوين ARIA.

## 🔌 واجهة REST

المصادقة الحالية ترويسة `X-User-Id` (طبقة تجريبية للتشغيل الداخلي).
**عند الدمج في ERP حقيقي:** استبدل استخراج المستخدم في `api.js:handleApi` بجلسة/توكن نظامك — ولا تغيّر شيئًا في `domain/`، فالصلاحيات والقواعد مفروضة هناك.

| الطريقة | المسار | ملاحظة |
|---|---|---|
| GET | `/api/time` | مرجع الوقت — بلا مصادقة |
| GET | `/api/bootstrap` | كل بيانات الإقلاع في نداء واحد |
| GET | `/api/dashboard` | البطاقات السبع + قائمة التجارب |
| GET/POST | `/api/trials` | القائمة / الإنشاء |
| GET | `/api/trials/:id` | التجربة + التدقيق + الإشعارات + الفاتورة |
| POST | `/api/trials/:id/return · /purchase · /extend · /cancel` | الإجراءات |
| POST | `/api/extension-requests/:id/approve · /reject` | مدير |
| GET | `/api/devices · /api/devices/:id` | المخزون + تاريخ التجارب |
| GET/POST | `/api/customers` | العملاء |
| GET | `/api/analytics?days=` · `/api/audit` | مدير |
| GET/POST | `/api/notifications…` | الإشعارات |
| GET/PUT | `/api/settings` | السياسة (مدير) |

كل استجابة: `{ ok, data, serverTime }` — أو `{ ok:false, error:{ code, message, details } }` برسالة عربية جاهزة للعرض.

## ⚙️ الإعدادات (قابلة للتعديل من الواجهة)

| المفتاح | الافتراضي | الأثر |
|---|---|---|
| `defaultDurationHours` | 24 | مدة التجربة |
| `maxTotalDurationHours` | 72 | سقف المدة شاملة التمديدات |
| `maxExtensions` / `maxExtensionHours` | 2 / 24 | حدود التمديد |
| `requireManagerApprovalForExtension` | true | تحويل طلب الموظف إلى طلب معلّق |
| `reminderBeforeMinutes` | 60 | تذكير العميل قبل النهاية |
| `endingSoonMinutes` / `criticalMinutes` | 180 / 60 | عتبات العدّاد |
| `depositRequired` / `minDepositIQD` | true / 50,000 | سياسة العربون |
| `termsText` / `termsVersion` | — | أي تعديل يرفع رقم النسخة، وتُحفظ نسخة الشروط داخل كل تجربة |
