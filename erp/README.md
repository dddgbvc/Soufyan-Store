# Soufyan ERP — فحص الجهاز (Device Inspection)

نظام مستقل داخل الـERP لفحص الهواتف وتقييم حالتها الفنية **قبل البيع أو الشراء أو الاستلام أو الصيانة**.
مبني بـ **HTML + CSS + JavaScript خام (Vanilla)** — بلا أطر عمل، بلا خطوة بناء، بلا اعتماديات.

> هذا النظام **ليس** «تجربة ٢٤ ساعة» و**ليس** «الحجز المسبق». منطق الأعمال مستقل تمامًا.
> المشترك بين الأنظمة الثلاثة فقط: **نظام التصميم** + **المخزون (Inventory)** + **بنية الزبائن (Customers)**.

---

## التشغيل

### الطريقة السريعة
افتح `erp/index.html` بالمتصفح مباشرة (يعمل من الملف المحلي).

### الطريقة الموصى بها — عبر خادم محلي
بعض الفحوصات (الكاميرا، المايك، الموقع، الحساسات) تتطلب **سياقًا آمنًا** (`https` أو `localhost`):

```bash
cd erp
python3 -m http.server 8000
# ثم افتح: http://localhost:8000/
```

أو باستخدام Node:

```bash
npx serve erp
```

**للفحص على الهاتف نفسه** (وهو الاستخدام الحقيقي): ارفع مجلّد `erp/` على أي استضافة تدعم HTTPS
(GitHub Pages، Netlify، Cloudflare Pages…) وافتح الرابط من الجهاز المراد فحصه.

## مسار العمل

1. **فحص جهاز جديد** — التعرّف على الجهاز بثلاث طرق:
   - `Scan IMEI` مسح باركود بالكاميرا (BarcodeDetector).
   - `Enter IMEI` إدخال يدوي مع تحقّق فوري من رقم Luhn.
   - `Select Device` اختيار من المخزون.
   - IMEI غير مسجّل ⇦ نموذج تسجيل جهاز جديد داخل المخزون المشترك.
2. **هوية الجهاز** — Brand · Model · Variant · Storage · Color · IMEI · Serial · OS Version.
3. **إعداد الفحص** — غرض الفحص (بيع/شراء/استلام/صيانة) + الفاحص + ربط اختياري بزبون.
4. **مساحة الفحص** — ١٨ مرحلة، تقدّم كلي بالنسبة المئوية، وقائمة مراحل بحالات ✓ / ⏳ / ○.
5. **النتيجة** — درجة صحة الجهاز من ١٠٠، التقدير، تفصيل لكل مجموعة، وقائمة الأعطال مع الملاحظات.
6. **التقرير** — مستند قابل للطباعة مرتبط بسجل الجهاز.
7. **السجل** — تاريخ فحوصات كل جهاز: `٠٨ أيلول — ٩٤/١٠٠`.

## المراحل الثمانية عشر

| # | المرحلة | # | المرحلة |
|---|---------|---|---------|
| 1 | Display الشاشة | 10 | Cellular شبكة الاتصال |
| 2 | Touch اللمس | 11 | NFC |
| 3 | Cameras الكاميرات | 12 | GPS تحديد الموقع |
| 4 | Audio الصوت | 13 | Sensors الحساسات |
| 5 | Microphones المايكروفونات | 14 | Face ID / Fingerprint |
| 6 | Battery البطارية | 15 | Buttons الأزرار |
| 7 | Charging الشحن | 16 | Vibration الهزّاز |
| 8 | Wi-Fi | 17 | Flash الفلاش |
| 9 | Bluetooth | 18 | Connectivity المنافذ والاتصال |

**القائمة تتوسّع وتتقلّص حسب نوع الجهاز**: كل اختبار له شرط انطباق يُقرأ من قدرات الموديل في المخزون
(`caps`)، فمثلًا اختبار NFC لا يظهر لموديل بلا NFC، واختبار Face ID لا يظهر لجهاز ببصمة فقط،
والجهاز اللوحي بلا شريحة يتخطّى مرحلة الشبكة الخلوية. غير المنطبق يُسجَّل `Not Supported` مع السبب،
ويمكن للفاحص إعادته للفحص اليدوي بضغطة.

## الاختبارات التفاعلية (ليست مربّعات اختيار فقط)

| الاختبار | ما ينفّذه فعليًا | واجهة المتصفح |
|---------|------------------|----------------|
| ألوان الشاشة | ٦ شاشات ملء الشاشة (أحمر/أخضر/أزرق/أبيض/أسود/رمادي) | Fullscreen API |
| تجانس الإضاءة | تدرّجات ودرجات رمادية بملء الشاشة | Fullscreen API |
| تغطية اللمس | شبكة ١٠×١٦ تُملأ بالسحب + نسبة تغطية حيّة ونجاح تلقائي عند ٩٩٪ | Pointer Events + Canvas |
| اللمس المتعدّد | عدّ الأصابع المتزامنة وأعلى رقم مسجَّل | Pointer Events |
| الكاميرات | معاينة حيّة + التقاط + قياس **الإضاءة** و**الوضوح** (تباين لابلاس) | getUserMedia + Canvas |
| الفلاش | تشغيل/إطفاء المصباح فعليًا | MediaStreamTrack `torch` |
| السمّاعة | نغمة ١kHz ومسح ترددي ٢٠٠Hz→٨kHz | Web Audio API |
| توازن القناتين | تشغيل اليمين واليسار منفصلين | StereoPannerNode |
| المايك | تسجيل حقيقي + مؤشر مستوى حيّ + قياس الذروة بالديسيبل + إعادة تشغيل | MediaRecorder + AnalyserNode |
| البطارية | نسبة الشحن وحالته وزمن الامتلاء/النفاد | Battery Status API |
| صحة البطارية | إدخال النسبة وتطبيق قاعدة القبول (٨٠٪ فأكثر) تلقائيًا | منطق النظام |
| الشحن | مراقبة ٤٥ ثانية وكشف بدء الشحن تلقائيًا | `chargingchange` |
| الشبكة | حالة الاتصال + نوعه + قياس زمن الاستجابة بثلاث عيّنات | Network Information + fetch |
| البلوتوث | توفّر المذياع + بحث فعلي عن جهاز قريب | Web Bluetooth |
| NFC | قراءة بطاقة فعلية بمهلة ٣٠ ثانية | Web NFC (NDEFReader) |
| GPS | زمن التقاط الإشارة ودقّتها بالأمتار | Geolocation |
| الحساسات | قراءات حيّة للتسارع والميل والبوصلة مع نجاح تلقائي عند تغطية المدى | DeviceMotion / DeviceOrientation |
| البصمة/الوجه | التحقق من وجود مستشعر تحقق على مستوى النظام | WebAuthn |
| الهزّاز | تشغيل أنماط اهتزاز | Vibration API |
| الأزرار | تسجيل حالة كل زر + التقاط مفاتيح الصوت إن أرسلها الجهاز | KeyboardEvent |

كل اختبار ينتج إحدى النتائج الأربع: **Passed · Failed · Skipped · Not Supported**، مع إمكانية إضافة ملاحظة.
عندما لا تدعم المنصّة واجهةً ما، يُسجَّل `Not Supported` **مع سبب واضح** بدل إظهار نتيجة كاذبة.

## معادلة الدرجة (Device Health Score)

```
الدرجة = (مجموع أوزان الاختبارات الناجحة ÷ مجموع أوزان الاختبارات المُختبَرة) × 100
```

- **المتخطّى وغير المدعوم لا يدخلان في المعادلة** — لكنهما يخفضان «التغطية» المعروضة في التقرير.
- **الاختبارات الجوهرية** (`critical`) — مثل اللمس، الشاشة، المايك، صحة البطارية، الشحن، الشريحة،
  المكالمة، وقفل الحساب — فشلها يضع سقفًا صارمًا على الدرجة:

| عدد الأعطال الجوهرية | 0 | 1 | 2 | 3+ |
|---|---|---|---|---|
| السقف الأعلى للدرجة | 100 | 65 | 50 | 35 |

**التقدير:**

| الدرجة | التقدير |
|---|---|
| 90–100 | Excellent — ممتاز |
| 80–89 | Very Good — جيد جدًا |
| 70–79 | Good — جيد |
| 50–69 | Needs Attention — يحتاج انتباه |
| 0–49 | Critical — حرج |

**الحالة النهائية (قرار العمل):**

| الحالة | الشرط |
|---|---|
| جاهز للبيع | ٨٥ فأكثر بلا أي عطل |
| صالح مع ملاحظات | ٧٠ فأكثر مع أعطال غير جوهرية |
| يحتاج صيانة | عطل جوهري واحد أو درجة أقل من ٧٠ |
| مرفوض | عطلان جوهريان أو درجة أقل من ٥٠ |

**التفصيل (Breakdown)** يُحسب بنفس المعادلة داخل كل مجموعة:
الشاشة · البطارية · الكاميرا · الصوت · الاتصال · الحساسات · أخرى.

## البيانات والتخزين

كل شيء يُحفظ في `localStorage` تحت مساحة الاسم `soufyan.erp.v1` عبر `ERP.db` فقط:

| المجموعة | المحتوى |
|---|---|
| `models` | كتالوج الموديلات وقدرات كل موديل |
| `devices` | وحدات الأجهزة (IMEI, Serial, الحالة، الملكية) |
| `customers` | الزبائن |
| `staff` | الفاحصون |
| `inspections` | جلسات الفحص ونتائجها وتقاريرها |
| `settings` | تفضيلات (المظهر، آخر فاحص، الجلسة النشطة) |

- الحفظ **تلقائي أثناء الفحص** — إغلاق المتصفح لا يفقد الجلسة، وتظهر بلافتة «أكمل الفحص».
- عند امتلاء الحصة أو المتصفح الخاص، ينتقل التخزين للذاكرة مع تنبيه واضح بدل الفشل الصامت.
- زر **نسخة احتياطية** في لوحة الـERP يصدّر كل البيانات كملف JSON.
- **الخصوصية:** إحداثيات GPS تُخزَّن مقرّبة لمنزلتين عشريتين فقط، وتسجيل المايك يبقى في ذاكرة المتصفح ولا يُحفظ ولا يُرفع.

## التصميم والحركة

- نظام تصميم واحد لكل أنظمة الـERP: بطاقات، ألواح زجاجية (Glassmorphism) للعناصر الثانوية،
  حواف متحدة المركز، وسلّم ظلال للارتفاع.
- مظهر فاتح وداكن (يتبع النظام افتراضيًا) مع كتم الانتقالات لحظة التبديل حتى لا «يتلطّخ» التغيير.
- حركة مضبوطة: منحنى نابضي بلا ارتداد للتقدّم والدخول، ارتداد خفيف فقط للحركات الناتجة عن لمسة.
  النجاح يُعلَن بومضة واحدة قصيرة، والفشل بحالة لونية واضحة **بلا** حركة مزعجة.
- يحترم `prefers-reduced-motion` و`prefers-reduced-transparency` و`prefers-contrast`.
- RTL أصيل بخصائص منطقية (`inset-inline`, `margin-inline`) لا بقلب يدوي.

## التوسعة

**إضافة اختبار جديد** — أضف كائنًا في `TESTS` داخل `catalog.js`:

```js
{ id: 'display.hdr', stage: 'display', category: 'display', weight: 2,
  ar: 'سطوع HDR', en: 'HDR Brightness',
  hint: 'شغّل مقطع HDR وقارن أعلى سطوع.',
  applies: function (caps) { return !!caps.hdr; } }
```

**إضافة مشغّل تفاعلي** — في `runners.js`:

```js
DI.runners.register('myTest', function (ctx) {
  ctx.mount.appendChild(/* واجهتك */);
  // ctx.setResult('passed', { metrics: {...} });
  return function cleanup() {};
});
```
ثم اربطه بالاختبار عبر `runner: 'myTest'`.

**إضافة موديل للمخزون** — أضفه إلى `SEED_MODELS` في `inventory.js` مع `caps` الصحيحة،
فتتكيّف خطة الفحص تلقائيًا.

**إضافة نظام ERP جديد** (تجربة ٢٤ ساعة / الحجز المسبق) — أنشئ `modules/<name>/` واستورد نفس ملفات
`shared/`، ثم أضف بطاقته في `erp/index.html`. لا تشارك منطق الأعمال بين الأنظمة — فقط الطبقة المشتركة.

## دعم المتصفحات

الأساس يعمل على كل متصفح حديث. الاختبارات التفاعلية تعتمد على توفّر الواجهة:

| الواجهة | Chrome/Edge (Android/سطح مكتب) | Safari (iOS) | Firefox |
|---|---|---|---|
| الكاميرا / المايك | ✓ | ✓ | ✓ |
| Battery Status | ✓ | ✕ (يُسجَّل Not Supported) | ✕ |
| Web Bluetooth | ✓ | ✕ | ✕ |
| Web NFC | ✓ (Android) | ✕ | ✕ |
| BarcodeDetector | ✓ | ✕ (يتحوّل للإدخال اليدوي) | ✕ |
| Vibration | ✓ | ✕ | ✓ |
| DeviceMotion/Orientation | ✓ | ✓ (بإذن صريح) | ✓ |
| Torch (الفلاش) | ✓ (Android) | ✕ | ✕ |

عند غياب أي واجهة يعرض النظام السبب ويسمح بالفحص اليدوي — لا نتائج مضلّلة.

## الطباعة

من شاشة النتيجة أو التقرير: زر **طباعة**. يُطبع التقرير وحده على A4 (بلا قوائم ولا أزرار)،
مع منع قطع الصفوف بين الصفحات ومساحة توقيع الفاحص والزبون.
