# شاشة تسجيل الدخول برمز PIN

هوية بصرية مدمجة: **شبكة لينكس التقنية** في الخلفية، **بطاقة أكريليك بأسلوب Fluent**،
و**مواد وحركة Apple** في كل ما يلمسه المستخدم — لوحة أرقام دائرية، استجابة عند
الضغط لا عند الإفلات، وسبرنغات فيزيائية بدل مُدد ثابتة.

---

الرمز الصحيح في الديمو: `1234`.

## 2. لماذا لا يوجد Tailwind ولا Motion من CDN

النسخة السابقة كانت تحمّل Tailwind وMotion وخطوط Google من الشبكة. شاشة كاشير تُقلع
عشرات المرات يومياً، وأحياناً على اتصال ضعيف أو بلا اتصال؛ أي تأخير في CDN يعني شاشة
بيضاء أمام الزبون. النسخة الحالية:

- **CSS مكتوب مباشرة** بتوكنز محدّدة الأدوار — لا إطار، لا خطوة بناء.
- **محرّك سبرنغ صغير داخل الملف** (نحو 60 سطراً) بدل مكتبة حركة كاملة.
- **خط النظام أولاً** (`SF Pro` / `SF Arabic` على أجهزة Apple، `Segoe UI` على ويندوز)
  — يظهر النص في الإطار الأول، ويأتي معه التحجيم البصري والتتبّع مضبوطين من النظام.

النتيجة: الملف كامل يعمل من القرص، والإقلاع فوري.

## 3. ما الذي أُصلح من النسخة السابقة

| المشكلة | الأثر | الحل |
| --- | --- | --- |
| `pointerdown` + `preventDefault()` على أزرار اللوحة | لا يصل حدث `click`، فلا تعمل الأزرار بلوحة المفاتيح إطلاقاً | الإبراز عند الضغط عبر `:active` في CSS، والتنفيذ عند الرفع عبر `click` — نفس سلوك النظام، والأزرار تعمل بـ Enter وSpace |
| `maximum-scale=1, user-scalable=no` | يمنع التكبير كلياً — مخالفة صريحة لإمكانية الوصول | أُزيل؛ بقي `viewport-fit=cover` فقط |
| لا يوجد مظهر داكن | شاشة بيضاء ساطعة في وردية ليلية | مظهران كاملان عبر `prefers-color-scheme` + مبدّل يدوي في الديمو |
| رسالة الخطأ نص عادي داخل `div` | لا يعلنها قارئ الشاشة | `role="status"` مع نص وأيقونة ولون (لا اللون وحده) |
| أزرار أيقونية بلا اسم | «زر» فقط عند قارئ الشاشة | `aria-label` وصفي لكل مفتاح |
| لا حلقات تركيز | لوحة المفاتيح تتنقّل بشكل أعمى | `:focus-visible` بحلقة 2px وإزاحة 3px |
| رسالة الخطأ تظهر وتختفي فيقفز التخطيط | اللوحة تتحرّك تحت الإصبع | صف الرسالة يحجز ارتفاعه دائماً |
| `select-none` على `body` كاملاً | يعطّل التحديد في كل الواجهة | حُصر في اللوحة والنقاط فقط |
| بطاقة الترحيب تستبدل البطاقة كلها | قفزة مكانية تكسر استمرارية السطح | نفس البطاقة تبقى مكانها ويتحرّك ارتفاعها فقط |
| `Escape` = حذف رقم واحد | مكرّر مع Backspace بلا فائدة | `Backspace` حذف رقم، `Escape` مسح الكل |
| الطول 6 ثابت فقط | لا يغطّي المطلوب (4–8) | `minLength` و`maxLength` مرنان، والنقاط تنمو مع الإدخال |

## 4. الهوية البصرية

### الخلفية

شبكة SVG بمستويين (44px دقيقة، 176px رئيسية) بشفافية منخفضة، فوقها تدرّج شعاعي
يخفّفها عند الأطراف، وتحتها هالتان ناعمتان — واحدة باردة وأخرى دافئة. الهالتان ليستا
زينة: الزجاج بلا شيء خلفه يكسره يبدو مسطّحاً.

### البطاقة

مادة أكريليك: `backdrop-filter: blur(30px) saturate(180%)` فوق أبيض بشفافية 74%،
مع **حافة مضيئة أعلاها** (`inset 0 1px 0`) تحاكي الضوء الساقط على حافة الزجاج،
وظلّان متراكبان — قريب حادّ وبعيد ناعم — بدل حدّ يزيّف الارتفاع.

**أنصاف الأقطار متراكزة:** البطاقة 34px، الحشو 22px، فالعناصر الملاصقة للحشو 12px
(`34 − 22`). هذا أكثر تفصيل يُفسد شعور الواجهات حين يُهمل.

### لوحة الأرقام

مفاتيح **دائرية** بتعبئة نظامية أغمق قليلاً من البطاقة — لا بيضاء فوق بيضاء. الأرقام
بخط Monospace بأرقام جدولية (`tabular-nums`) فلا يتغيّر عرضها. مقاس المفتاح:

```css
--key-size: clamp(52px, min(19vw, 9.4dvh), 84px);
```

يتقلّص مع العرض **والارتفاع** معاً، فتظل اللوحة كاملة على iPhone SE وتصبح مريحة
جداً على iPad.

### الخطوط

خطّان فقط: خط النظام للنصوص العربية، وMonospace للأرقام. التتبّع يتبع الحجم —
سالب `0.02em` في عنوان الترحيب (22px)، وسالب `0.014em` في ترويسة النظام (17px)،
ومحايد في النص الصغير.

## 5. الحركة

كل حركة هنا **سبرنغ** يُعرَّف بزمن الوصول (`response`) ومقدار التجاوز (`bounce`)،
لا بمدة ثابتة ومنحنى. السبب: السبرنغ قابل للمقاطعة وإعادة التوجيه مع احتفاظه بسرعته،
فلا يصطدم بجدار حين يعكس المستخدم اتجاهه.

| الحالة | الحركة |
| --- | --- |
| إدخال رقم | نبضة النقطة `1.42 → 1`، تجاوز `0.34`، وصول `0.30s` |
| خطأ | اهتزاز = سبرنغ هدفه صفر بسرعة ابتدائية `265px/s` وتجاوز `0.62` — يتلاشى فيزيائياً بدل مسار مرسوم |
| نجاح | الشبكة تتمدّد للخارج وتتلاشى مع ضبابية حركة، والبطاقة تتبدّل من الداخل |

**تسلسل النجاح ≈ 330ms** حتى استقرار بطاقة الترحيب:
انفجار الشبكة يبدأ فوراً · خروج طبقة الإدخال 120ms ·
دخول الترحيب (شفافية + حجم + ضبابية) 320ms متداخلة معه.

عند `prefers-reduced-motion: reduce` تصل كل السبرنغات لقيمتها النهائية فوراً، ويُلغى
انفجار الشبكة والاهتزاز — والتغذية الراجعة تبقى كاملة عبر اللون والنص، لأن الحركة
ليست قناة الإخبار الوحيدة في أي حالة هنا.

## 6. الألوان

الطبقتان مفصولتان: **Primitives** تُسمّى بالدرجة (`--n-900`، `--blue-600`) ولا
تُستخدم داخل المكوّنات، و**Semantics** تُسمّى بالدور (`--surface-card`،
`--text-secondary`) وهي وحدها ما تشير إليه العناصر. هذا الفصل هو ما يجعل المظهر
الداكن تبديل توكنز لا مراجعة كل استخدام.

أزواج قِيست على الخلفية التي تُرسم عليها فعلاً (WCAG 2.1):

| الزوج | النسبة | المطلوب |
| --- | --- | --- |
| نص أساسي `#1c1c1e` على البطاقة | ‎15.1:1 | 4.5 ✓ |
| نص ثانوي `#6b6b70` على البطاقة | ‎4.9:1 | 4.5 ✓ |
| أبيض على زر الدخول `#0069d9` | ‎5.2:1 | 4.5 ✓ |
| نص الخطأ `#d70015` على البطاقة | ‎5.1:1 | 4.5 ✓ |
| نص الدور `#17803d` على شارته | ‎4.7:1 | 4.5 ✓ |
| نص ثانوي `#98989d` على البطاقة الداكنة | ‎5.5:1 | 4.5 ✓ |
| أبيض على دائرة النجاح `#248a3d` | ‎4.4:1 | 3.0 ✓ (رسم) |

اللون لا يحمل معنى وحده في أي مكان: الخطأ لون **و**أيقونة **و**نص، وحالة الجاهزية
تغيير تعبئة **و**نص الزر.

## 7. الواجهة البرمجية

```ts
interface PinLoginScreenProps {
  onSuccess: (pin: string) => Promise<{
    success: boolean;
    employeeName?: string;
    roleName?: string;
    message?: string;      // رسالة خطأ من الخادم تحلّ محل النص الافتراضي
  }>;
  onForgotPin: () => void;
  onPasskeyLogin: () => void;
  systemName?: string;     // الافتراضي: "نظام نقاط البيع"
  minLength?: number;      // 4–8، الافتراضي 4
  maxLength?: number;      // 4–8، الافتراضي 6
  onVerified?: () => void; // لحظة نجاح التحقّق — لتفجير شبكة الخلفية
  onFinish?: () => void;   // بعد استقرار الترحيب — الانتقال للشاشة التالية
}
```

نسخة Vanilla بنفس الخيارات:

```js
const screen = PinLogin.create(document.getElementById("mount"), { /* الخيارات */ });
screen.destroy();   // يزيل مستمعي لوحة المفاتيح ويفرّغ الحاوية
```

**حين `minLength === maxLength`** يُرسل الرمز تلقائياً عند اكتمال آخر رقم — أسرع
مسار للكاشير. وحين يختلفان تظهر نقطة مفرغة إضافية تلمّح أن الرمز يقبل المزيد،
والتأكيد بزر «دخول» أو Enter.

`employeeName` و`roleName` يُدرجان كنص (`textContent`) لا كـ HTML، لأنهما يأتيان
من الخادم.

## 8. إمكانية الوصول

- كل مفتاح `<button>` حقيقي باسم وصفي، ويعمل بالفأرة واللمس ولوحة المفاتيح.
- مساحات اللمس: المفاتيح 52–84px، والأزرار المساعدة 46px — فوق حد 44×44 المريح.
- `role="status"` للرسائل، و`aria-label` حيّ على صف النقاط يعلن «3 من 4 أرقام».
- تدعم `prefers-reduced-motion` و`prefers-reduced-transparency` و`prefers-contrast: more`
  و`forced-colors: active` (يُلغى الزجاج وتظهر حدود من ألوان النظام).
- التكبير حتى 200% يعمل، والتخطيط ينساب حتى عرض 320px بلا تمرير أفقي.
- على الشاشات القصيرة تلتصق البطاقة بالأعلى وتصبح قابلة للتمرير بدل أن تُقص من
  الطرفين (`align-content: safe center`).

## 9. ملاحظات قبل الإنتاج

هذا مكوّن واجهة؛ ما يلي خارج نطاقه ويحتاج قراراً من جانب الخادم:

1. **حدّ المحاولات:** لا يوجد إيقاف مؤقت بعد محاولات خاطئة متكرّرة. يُنفَّذ في
   الخادم ثم يُعرض عبر `message` في نتيجة `onSuccess`.
2. **الرمز في الذاكرة:** يبقى في متغيّر جافاسكربت حتى نهاية الطلب. لا يُسجَّل ولا
   يُحفظ في أي تخزين.
3. **PassKey:** الزرّ يستدعي `onPasskeyLogin` فقط؛ تدفّق WebAuthn نفسه لم يُنفَّذ.
