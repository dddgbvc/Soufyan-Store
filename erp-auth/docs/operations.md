# التشغيل اليومي — Operations

## إنشاء موظف

**من الواجهة** (يتطلب `employees.create`)

1. لوحة التحكم ← الموظفون ← «إضافة موظف».
2. الاسم إلزامي. البريد اختياري لكنه **شرط استرجاع الرمز** — بدونه لا يستطيع
   الموظف استعادة رمزه بنفسه.
3. رمز الدخول الأولي اختياري. عند تعيينه يُطلب من الموظف تغييره عند أول دخول.
4. الصلاحيات تُسند بعد الإنشاء من شاشة تفاصيل الموظف (تتطلب `employees.permissions`).

الرمز الوظيفي يُولَّد تلقائياً بصيغة `EMP-0001` إن لم يُحدَّد.

**عبر الـAPI**

```http
POST /api/employees
Content-Type: application/json
x-csrf-token: <من كوكي erp_auth_csrf>

{
  "fullName": "أحمد",
  "email": "ahmed@example.com",
  "jobTitle": "كاشير",
  "initialPin": "483916",
  "permissions": ["cashier.view", "cashier.create_sale"]
}
```

## إسناد الصلاحيات

الموظفون ← اختر الموظف ← «إدارة الصلاحيات».

المحرر شجرة بالأقسام: مربّع القسم يفعّل أو يلغي فرعه كاملاً، والصلاحيات الحسّاسة
مُعلَّمة. الحفظ يستبدل المجموعة كاملة بما هو محدّد، ويُسجَّل الفرق (المضاف والمحذوف)
في سجل التدقيق.

**غير مسموح** — ولو ظهر لك الزر: تعديل صلاحياتك أنت، أو المساس بحساب مالك وأنت لست
مالكاً.

## تعيين رمز أولي

الموظفون ← الموظف ← «تعيين رمز دخول أولي».

- يجب ألا يطابق رمز موظف آخر.
- يجب أن يجتاز سياسة القوة (لا متسلسل، لا مكرّر، لا متناظر).
- يُعلَّم تلقائياً «يجب التغيير عند أول دخول».
- كل جلسات الموظف تُنهى فوراً.

سلّم الرمز شفهياً أو عبر قناة خاصة — لا ترسله في رسالة تبقى محفوظة.

> **انتبه:** من يملك `employees.update` يستطيع تعيين رمز لأي موظف غير مالك، أي
> الدخول بحسابه فعلياً. هذه طبيعة صلاحية إعادة تعيين بيانات الاعتماد في أي نظام؛
> امنحها بحذر وراجع أحداث `pin.assigned` في سجل التدقيق.

## تعطيل وإعادة تفعيل

الموظفون ← الموظف ← «تعطيل الحساب».

التعطيل فوري الأثر: كل الجلسات تُنهى، و`has_permission` تُرجع false لكل مفتاح،
ورمز الدخول يُرفض حتى لو كان صحيحاً. لا تُفقد المنح — إعادة التفعيل تستعيد كل شيء
كما كان، وتصفّر عدّاد المحاولات وأي إيقاف مؤقت.

فضّل التعطيل على الحذف: الحذف يزيل الحساب نهائياً، وسجل التدقيق يحتفظ بالمعرّف
لكن يفقد الاسم.

## إنهاء الجلسات

- **مديراً:** الموظفون ← الموظف ← «إنهاء كل جلساته».
- **موظفاً:** القائمة العلوية ← «حسابي وأجهزتي» ← «إنهاء» لجهاز بعينه أو «إنهاء
  بقية الجلسات».

كل موظف يرى أجهزته وآخر نشاط لكل جهاز — وهي أسرع طريقة لاكتشاف جلسة لا يعرفها.

## قراءة سجل التدقيق

لوحة التحكم ← الإعدادات (يتطلب `settings.view`). مرشِّح «الإخفاقات فقط» يعزل
الأحداث المشبوهة.

راجع دورياً: `login.blocked`، `authz.denied`، `employee.permissions_changed`،
وأي `digest_mismatch`.

## الصيانة

```sql
select * from erp_auth.purge_expired(30);
```

يومياً عبر `pg_cron` أو أي مجدول. سجل التدقيق لا يُمسّ.

## استكشاف الأعطال

| العرض | السبب المرجّح |
|---|---|
| «تعذّر التحقق من الطلب» | `APP_URL` لا يطابق الأصل الحقيقي، أو كوكي CSRF محجوب |
| كوكي الجلسة لا يُحفظ | HTTPS مفقود في الإنتاج (`Secure`) |
| كل الرموز مرفوضة فجأة | تغيّر `AUTH_PIN_PEPPER` |
| «هذا الرمز مستخدم من قبل موظف آخر» | التفرّد مطلوب لعمل الدخول بالرمز وحده |
| لا يصل بريد الاسترجاع | `MAIL_PROVIDER=console`، أو الموظف بلا بريد، أو حسابه معطّل |
| «غير مفعّلة على هذا النظام» لطريقة البريد | متغيّرات Supabase غير مضبوطة |
| `qr_expired` عند الاستهلاك | انتهت المهلة، أو الاستهلاك من جهاز غير الذي أنشأ التحدي |
