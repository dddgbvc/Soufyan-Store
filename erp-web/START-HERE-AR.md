# ياقوت — الكود الكامل لتطبيق الويب

> **ابدأ بـ UPGRADE-AR.md** للإصدار 7: الدخول صار بحساب المحل ثم PIN، والبيانات من Supabase، وأُزيل الاعتماد على هوية ChatGPT Sites.

هذه حزمة مصدر آخر نسخة منشورة (الإصدار 6، بتاريخ 8 نوفمبر 2026) لمكتب سفيان للموبايل.
ابدأ بقراءة هذا الملف ثم README.md وPUSH_OPERATIONS.md.

## المحتويات والحالة الحالية
- واجهة عربية RTL وعملة IQD ووضع نهاري وليلي.
- المبيعات والفواتير، الديون والدفعات، المخزون، الخزائن، الموردون، معدات الإنترنت والمستعمل، البكجات، الشحن وISP.
- صفحات بحث وفلاتر وتقارير وبيانات تجريبية قابلة للتعديل وحفظ محلي وتصدير/استيراد JSON.
- خطوط ثمانية وكايرو والمسيري، مع ملفات الخطوط/التضمين وتراخيصها المتاحة، وترحيب متحرك.
- Web Push حقيقي: Service Worker وتسجيل أجهزة وقاعدة D1 وسجل إرسال ومفاتيح VAPID من بيئة الخادم.
- تجربة دفعة من 1 إلى 5 إشعارات بفاصل لا يقل عن 5 ثوانٍ، مع حماية من إعادة إرسال نفس الطلب.
- ملف تبعيات مقفل، اختبارات وتحديثات SQL ومكونات الواجهة كاملة.

هذه نسخة الويب التي بنيناها هنا، وليست كود برنامج Electron الأصلي ولا نسخة iOS أصلية.
أقسام ERP تستخدم localStorage وبيانات نموذجية. Supabase والشحن وISP ليست متصلة فعلياً؛ صفحة المزامنة محاكاة وليست محرك مزامنة إنتاجياً. بيانات الإشعارات وحدها محفوظة على الخادم.

## تشغيل التطوير على جهازك
المتطلبات: Node.js 22.13 أو أحدث، ومدير pnpm المطابق لـpackage.json (11.25.0).
فك الضغط، وافتح الطرفية داخل مجلد Yaqoot-ERP-WebApp:

```sh
npx pnpm@11.25.0 install --frozen-lockfile
npx pnpm@11.25.0 dev
```

المنفذ الافتراضي في وضع التشغيل المحمول هو 5173؛ استخدم الرابط الذي تعرضه الطرفية.
الواجهة التجريبية يمكن عرضها دون إعداد قاعدة الإشعارات. لا تتوقع عمل الإشعارات قبل ضبط البيئة والهوية وقاعدة D1.

للفحص والبناء:
```sh
npx pnpm@11.25.0 exec tsc --noEmit
node --experimental-strip-types --test tests/push.test.mjs
npx pnpm@11.25.0 build
```

لتجهيز جداول الإشعارات محلياً بعد البناء:
```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_slippery_black_widow.sql
```

السكربتات المرفقة تختار وضع portable عند غياب إعدادات بيئة Sites المحلية. أوامر README القديمة التي تذكر أدوات Sites تخص إعادة النشر من البيئة الأصلية؛ أوامر هذا الدليل تستعمل سكربتات المشروع المتاحة لديك.

## إعداد الإشعارات لاحقاً
1. أنشئ قاعدة D1 واربطها باسم DB، وطبّق ملف migration المرفق على القاعدة المقصودة.
2. أضف VAPID_PUBLIC_KEY وVAPID_PRIVATE_KEY وVAPID_SUBJECT في متغيرات الخادم. يوجد .dev.vars.example بقيم فارغة للتوضيح؛ لا يحتوي مفاتيح حقيقية.
3. لبيئة جديدة، ولّد زوج مفاتيح جديداً باستخدام web-push واحفظه بأمان. لاستمرار نفس الموقع وأجهزته، حافظ على زوج مفاتيحه الموجود في إعدادات الاستضافة؛ لا تستبدله عشوائياً.
4. الإشعارات تتطلب HTTPS في النشر وإذن المستخدم. على الآيفون تُفعّل من تطبيق الويب المضاف للشاشة الرئيسية.
5. تغيير الدومين يعني إعادة تسجيل الأجهزة على الدومين الجديد. الحزمة لا تتضمن اشتراكات أجهزة أو سجلات إرسال الإنتاج.
6. ملف scripts/push-admin.py مرتبط بعنوان الموقع الحالي ويستعمل مصادقة Sites. عدله وفق نظام الهوية والعنوان الجديد قبل استعماله مع استضافة أخرى.

## نقطة أساسية قبل النقل خارج Sites
كود الهوية في app/chatgpt-auth.ts يعتمد على رؤوس موثوقة يحقنها خادم Sites، وليس على تحقق مستقل من JWT.
المسار الخدمي في lib/push/server.ts يعتمد على بوابة الموقع الخاصة بالمالك. رأس X-Yaqoot-Operation وحده ليس مصادقة.
قبل نشر نسخة عامة أو نقلها لاستضافة أخرى: استبدل هذا الاعتماد بتحقق جلسة/رمز على الخادم وصلاحيات مالك، وأزل مسار الخدمة غير الموثق. لا تثق برؤوس هوية يرسلها العميل مباشرة.
ملف .openai/hosting.json يحمل هوية الموقع الأصلي لأغراض المطابقة؛ لا تستخدمها لإنشاء موقع جديد أو نشر بديل من غير قصد. إعدادات D1 في vite.config.ts تحتوي معرفاً محلياً وهمياً ويجب ربط الاستضافة الجديدة بالقاعدة الصحيحة.

## خريطة الربط مع النظام الحقيقي
- app/data.ts: الأنواع ومخطط الحقول والبيانات النموذجية.
- app/page.tsx: صفحات ERP وعمليات العرض والحفظ المحلي؛ استبدل الوصول للبيانات بطبقة خدمات تدريجياً.
- app/globals.css: الثيم والتجاوب والتصميم.
- app/welcome.tsx وملفات الخطوط: ترحيب الدخول والخطوط.
- app/push-settings.tsx وpublic/sw.js وapp/api/push/: الإشعارات.
- db/schema.ts وdrizzle/: قاعدة تسجيل الأجهزة وسجل الإرسال.
- worker/index.ts وvite.config.ts: بيئة الخادم والبناء.

في الربط الحقيقي افصل الحسابات/المخزون عن الواجهة، وتحقق من الصلاحيات على الخادم، واستخدم معاملات ذرية ومفاتيح idempotency وترقيم فواتير وتكلفة تاريخية وسجل تدقيق. الربط بـSupabase أو SQL يحتاج تصميم جداول وواجهات ومزامنة، وليس وضع مفتاح اتصال فقط.

## صوت الإشعارات ونسخة iOS
الإشعارات التي اختبرناها هي Web Push. صوت فلوس مخصص لإشعار شاشة القفل غير منفذ هنا. يحتاج تطبيق iOS بإشعارات أصلية وأصوات مضمّنة؛ يمكن إعادة استخدام تصميم الواجهة وخدمات البيانات، لكن يجب إضافة مشروع iOS ونظام APNs وإدارة الأجهزة. هذه الحزمة لا تدّعي أنها تحتوي تلك النسخة.

## ما لم يُضمّن
لا توجد مفاتيح VAPID الخاصة أو رموز وصول أو كلمات مرور أو قاعدة بيانات إنتاجية أو ملفات node_modules أو .git أو مخلفات البناء. التبعيات تُثبت من ملف pnpm-lock.yaml. الملفات الأصلية الملتزمة في النسخة المنشورة موجودة كاملة؛ تمت إضافة هذا الدليل وملف مثال البيئة وبيانات الإصدار فقط.

## التحقق
نجحت اختبارات TypeScript والبناء واختبارات التشفير وService Worker وفاصل الدفعات قبل نشر هذا الإصدار. نجحت الإشعارات الحقيقية وأكد المستخدم وصولها على الآيفون. لم تُختبر هذه الحزمة على جهاز Windows أو استضافة مختلفة؛ اقرأ متطلبات الهوية والبيئة قبل النقل.
